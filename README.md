# Agora Conversational AI - Custom TTS Recipe (Python)

The **custom TTS** recipe in the Agora Conversational AI recipes family. It uses
`GenericTTS` to send the LLM's text to your own OpenAI-compatible HTTP endpoint.
The endpoint streams raw PCM audio back to Agora, which plays it to the user over
RTC.

**Pipeline:** `DeepgramSTT(nova-3, en)` -> `OpenAI(gpt-4o-mini)` (managed) ->
`GenericTTS(CUSTOM_TTS_URL)`

This repository includes a provider-free mock TTS endpoint. It generates a
deterministic tone rather than speech, so the complete HTTP TTS path can be tested
before replacing the mock with a real synthesizer.

## Prerequisites

- [Python 3.10+](https://www.python.org/)
- [Bun](https://bun.sh/)
- [ngrok](https://ngrok.com/) or another public tunnel
- Agora App ID + App Certificate (the [Agora CLI](https://github.com/AgoraIO/cli) makes this easy)

The same commands work on macOS, Linux, and Windows. On macOS/Linux, setup uses
`python3`; on Windows, it uses the Python launcher (`py`) or `python`. WSL and
virtualenv activation are not required.

## Run it

```bash
# 1. Install web dependencies and create the Python virtual environment
bun run setup

# 2. Add Agora credentials, or edit server/.env.local manually
agora login
agora project use <your-project>
agora project env write server/.env.local

# 3. Expose the backend. Agora cloud calls the mounted custom TTS endpoint.
ngrok http 8000

# 4. Add the custom TTS settings to server/.env.local
# CUSTOM_TTS_URL=https://<your-tunnel>.ngrok-free.dev/tts/v1/audio/speech
# CUSTOM_TTS_APP_ID=<your-custom-tts-app-id>

# 5. Start the backend and web app
bun run dev
```

Open [http://localhost:3000](http://localhost:3000), start a conversation, and
speak. The mock endpoint returns a tone for each agent reply.

## Architecture

```text
Browser (localhost:3000)
  |  /api/*
  v
Next.js  --rewrite-->  FastAPI backend (localhost:8000)
                            |  starts the agent with GenericTTS(CUSTOM_TTS_URL)
                            v
                       Agora ConvoAI Cloud
                            |  Deepgram STT -> OpenAI LLM
                            |  POST <CUSTOM_TTS_URL> (Authorization: Bearer ...)
                            v
                       Custom HTTP TTS endpoint
                       (mounted at /tts, public through ngrok)
                            |  raw PCM16 / 24 kHz / mono
                            v
                       Agora cloud -> RTC audio
```

The FastAPI process serves both the agent lifecycle API and the mounted custom
TTS endpoint. See [ARCHITECTURE.md](./ARCHITECTURE.md) for the security and
deployment implications.

## Environment variables

Backend env template: [`server/.env.example`](server/.env.example).

| Variable | Required | Default | Notes |
| --- | :---: | :---: | --- |
| `AGORA_APP_ID` | Yes | - | Agora Console project App ID |
| `AGORA_APP_CERTIFICATE` | Yes | - | Agora Console App Certificate; server only |
| `CUSTOM_TTS_URL` | Yes | - | Public HTTP(S) endpoint ending in `/tts/v1/audio/speech`; Agora cloud cannot call localhost |
| `CUSTOM_TTS_API_KEY` | Yes | `any-key-here` | Shared endpoint key; Agora sends it as `Authorization: Bearer <key>` |
| `CUSTOM_TTS_APP_ID` | Yes | - | App ID forwarded to the custom TTS endpoint; not the Agora project App ID |
| `CUSTOM_TTS_MODEL` |  | `mock-tts` | Model value sent to the endpoint |
| `CUSTOM_TTS_VOICE` |  | `mock-voice` | Voice value sent to the endpoint |
| `AGENT_GREETING` |  | built-in | Opening line synthesized by the custom endpoint |
| `PORT` |  | `8000` | Backend port |
| `AGENT_BACKEND_URL` | web deploy only | - | Backend URL used by Next.js `/api/*` rewrites |

`server/requirements.txt` installs `agora-agents` from PyPI. A narrow adapter in
`server/src/agent.py` maps the published SDK's `GenericTTS` configuration to the
cloud `generic_http` vendor name.

## Custom TTS contract

Agora sends an OpenAI-compatible JSON request:

```json
{
  "input": "Text generated by the LLM",
  "app_id": "your_custom_tts_app_id",
  "instruction": "Please use standard American English, natural tone, moderate pace, and steady intonation",
  "model": "mock-tts",
  "voice": "mock-voice",
  "speed": 1,
  "sample_rate": 24000,
  "response_format": "pcm"
}
```

The endpoint must accept `Authorization: Bearer <CUSTOM_TTS_API_KEY>` and return
HTTP 200 with raw little-endian PCM16, 24 kHz, mono audio bytes. It may stream
those bytes using chunked HTTP transfer.

## Commands

```bash
bun run setup            # install web and server dependencies
bun run dev              # run backend (:8000) and web (:3000)

bun run doctor           # check shared prerequisites
bun run doctor:local     # also check local env and public custom TTS URL

bun run verify           # web checks, no Agora credentials needed
bun run verify:local     # backend tests, endpoint smoke checks, and web build
bun run clean            # remove virtualenv and generated build files
```

CI follows the other Python recipes: backend tests run on Linux, macOS, and
Windows with Python 3.10 and 3.13; the web app is verified with Bun. Docker build
and smoke-test workflows are included separately.

## Replacing the mock

Replace `_generate_tone()` in [`server/src/tts.py`](server/src/tts.py) with your
TTS implementation, or point `CUSTOM_TTS_URL` at another compatible public
service. Keep the request fields, authorization, and raw PCM response contract.
The endpoint module intentionally has no dependency on `agora-agents`.

## Troubleshooting

| Problem | Fix |
| --- | --- |
| Agent starts but custom TTS receives no requests | Verify `CUSTOM_TTS_URL` is public, uses HTTP(S), and ends in `/tts/v1/audio/speech` |
| TTS reports 401 | Use the same non-empty `CUSTOM_TTS_API_KEY` in the Agent config and endpoint |
| Audio is garbled or silent | Return raw PCM16 little-endian, 24 kHz, mono bytes; do not return WAV headers or MP3 |
| `doctor:local` warns about localhost | Replace the local URL with the tunnel URL |
| Local calls fail behind a proxy | Route localhost and private addresses directly in the proxy configuration |
| `server/venv` is missing during verification | Run `bun run setup` |
